# MASC Landing

Goal: a production-ready landing for a MASC campaign in `src/app/landings/<slug>/`, visually consistent with the existing MASC pages, whose form reliably lands leads in n8n, previewed on Vercel before merge.

Reference implementation — copy from it, don't reinvent: `src/app/landings/ai-agents-marathon/`.

## 1. Brief (ask 3–5 questions max, then build)

Collect, or mark as an explicit assumption if the user doesn't know yet:

1. **Campaign + slug** — name, URL slug (`ai-agents-marathon`), whether it should also be the site root `/`.
2. **Offer** — format, duration, price or «безкоштовно», start date (or «надішлемо на email»).
3. **Audiences** — 2–4 segments: key (`switcher`), toggle label, form label, one headline + 1–2 sentences each.
4. **Program / what's inside** — items per day/module. Don't pad them with invented detail; if you extend a title into sub-points, say so in the final summary.
5. **Visual preset** — see `references/design.md` (dark-lime is the default for AI-agent campaigns).

If the user gives a `CLAUDE_LANDING_PROMPT.md`-style brief, follow it, except where it conflicts with the rules below — then follow the rules and say what you changed.

### Copy rules (non-negotiable)
- Ukrainian by default; «ти»-form for B2C.
- No guaranteed results or invented numbers: no «10x», «заощадиш 15 год/тиждень», «$1–3K», graduate counts, unless the user supplies the figure and confirms it is real. Use «потенційно», «покажемо як», concrete deliverables instead.
- Only real cases/speakers. Never invent testimonials, logos or partners.

## 2. Build

Read `AGENTS.md` first: this is Next.js 16 — check `node_modules/next/dist/docs/` before using an API you're unsure about.

Files in `src/app/landings/<slug>/` (mirror the reference):

| File | Role |
| --- | --- |
| `page.tsx` | Server component: `export const metadata` + renders the client component |
| `<Name>Landing.tsx` | `"use client"`: audience state, form, submit |
| `content.ts` | All copy + `SOURCE = "<slug>"`. Edits to text happen here only |
| `<slug>.module.css` | CSS Module, tokens at the top of `.page` |
| `Icon.tsx`, `*Graphic.tsx` | Inline SVG only (no icon/UI libraries) |
| `README.md` | Env, webhook, checklist (copy the reference and adapt) |
| `facebook-creatives.md` | 3 ad variants per segment, same copy rules |
| `preview.html` | Generated by `scripts/snapshot.mjs`, never hand-written |

Root route: `src/app/page.tsx` → `export { default, metadata } from "./landings/<slug>/page";` (only one landing can own `/`; ask before replacing the current one).

Hard rules:
- **No Tailwind classes, no external UI/icon libraries.** CSS Modules + inline SVG.
- **Form posts to `/api/lead`, never to n8n directly.** Payload `{ email, audience, source }` (+ optional `utm` with `utm_source|medium|campaign|content|term` read from the page URL; invalid values are dropped by the route); the route adds `timestamp`, validates, and forwards to `WEBHOOK_URL` / `NEXT_PUBLIC_WEBHOOK_URL` read at request time. Don't touch the route unless the payload contract changes (then update every landing).
- Never hardcode the webhook URL.
- Audience toggle and form `<select>` share one state (two-way sync).
- States: `sending` (button disabled), `success` (`<output>` «Дякуємо! Перевір email», back to form after 5 s), `error` (`role="alert"`). Map 503 → «Реєстрація тимчасово недоступна», anything else → «Не вдалося надіслати заявку…».
- Mobile-first, 44px+ touch targets, no horizontal scroll at 320px, visible focus rings, `aria-pressed` on toggle buttons, `prefers-reduced-motion` respected.
- Biome lint gotchas: use `<output>` instead of `role="status"`; `preview.html` is excluded in `biome.json`.

## 3. Verify (before any push)

```bash
pnpm lint
pnpm build            # landing routes must be ○ static, /api/lead ƒ dynamic
node .claude/skills/masc-landing/scripts/fake-webhook.mjs &          # :3999, logs payloads
WEBHOOK_URL=http://127.0.0.1:3999/hook PORT=3456 pnpm start &
node .claude/skills/masc-landing/scripts/check-landing.mjs http://localhost:3456/landings/<slug>
node .claude/skills/masc-landing/scripts/snapshot.mjs http://localhost:3456/landings/<slug> src/app/landings/<slug>/preview.html
```

`check-landing.mjs` asserts: no horizontal scroll at 375/1280, toggle↔select sync, invalid-email error, success state + reset after 5 s; it saves `landing-mobile.png` / `landing-desktop.png` — look at them and send them to the user. Confirm the payload line in the fake-webhook log.

Kill servers by PID, not `pkill -f <pattern>`: a pattern that appears in your own command line kills your shell.

## 4. Deliver

Commit on the working branch, push, open a PR. **Never hand the user the branch-alias URL** from the `vercel[bot]` comment (`my-app-git-<branch>-…vercel.app`) — it doesn't open for them. Tell them to open Vercel → Deployments → the newest Preview row for the branch → **Visit**, which gives the working hash URL `my-xxxxxxxxx-maia-ai2.vercel.app`; if they send it back, use that one from then on. Then walk the user through `references/deploy.md` — env vars, which deployment to open, domain. Final message: what was built, what deviates from the brief and why, what's assumed, what the user must do before launch.

## Troubleshooting (what the user will report)

| User sees | Cause | Fix |
| --- | --- | --- |
| «Реєстрація тимчасово недоступна» | `/api/lead` → 503: env var not in **this** deployment | Enable var for Preview *and* Production, then Redeploy *that* deployment |
| «Не вдалося надіслати заявку…» | 502: n8n rejected/unreachable | Vercel → deployment → Logs, line `[lead] …`; check URL, n8n workflow active (`/webhook/` needs active, `/webhook-test/` needs "listen") |
| Next.js starter page «To get started, edit page.tsx» | They opened a Production deploy of `main` before merge | Open the branch's Preview deployment, or merge the PR |
| Preview link doesn't open / Chrome «Did you mean claude.ai?» | You gave the branch-alias URL | Give Vercel → Deployments → newest Preview row → Visit (hash URL `my-xxxxxxxxx-maia-ai2.vercel.app`) instead |
| Can't reach next.masc.space / vercel.app from the sandbox | Egress policy | Ask for screenshots, or for the host to be allowed in environment network settings |
